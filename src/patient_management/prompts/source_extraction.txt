TASK
Copy into JSON what the SOURCE literally states about the patient. Do not interpret, infer, summarize, diagnose, or advise.

OUTPUT
Exactly one JSON object. No Markdown, no code fences, no text before or after it.

RULES
1. Extract only what is explicitly written. If unsure, leave it out. Empty arrays are correct when nothing applies.
2. Every item needs "quote": the exact source words it comes from (copy, do not retype; max 200 characters).
3. Copy wording verbatim. Never rename, abbreviate, translate, correct, standardize, or add codes.
4. Every number, unit and date you output must appear in that item's quote exactly as written.
5. Keep negation and uncertainty words inside "text" (无, 否认, 未见, (-), 考虑, 可能, 待排, 不除外, ?).
   Set "assertion" from those words only: "absent" (negated), "uncertain" (hedged), "present" (plainly stated),
   "unknown" if the wording is ambiguous. Never make a statement more or less certain than the source.
6. "stated_diagnoses": only items of an explicit diagnosis list (入院诊断, 初步诊断, 目前诊断, 出院诊断, 诊断 ...)
   or a plain statement that the patient has the disease. Hedged items (考虑…, …可能, 待排, 不除外, ?) are NOT
   diagnoses: put them in "facts" with "kind": "impression" and "assertion": "uncertain".
   Never take items from 鉴别诊断 or 诊断依据.
7. "diagnosis_updates": only when the source explicitly revises, resolves or revokes a diagnosis listed in CONTEXT.
8. "explicit_tasks": only plans or orders that are written (计划, 拟, 予, 医嘱, 复查 ...). Never invent tasks.
9. "stated_admission_date": only if the source writes 入院日期/入院时间 or "<date>入院". Never use a note's own date.
10. Do not extract labs from lines listed under ALREADY CAPTURED.
11. Times ("collected_at_text", "performed_at_text", "observed_at_text", "due_text") must be copied from the source,
    otherwise null. Never compute or guess a date.
12. Use only the English enum values listed under FIELDS.
